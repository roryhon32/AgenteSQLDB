Milia AI — Agente SQL & Plataforma Analítica

Documentação técnica de arquitetura, esteiras de governança, isolamento Zero-Trust e engenharia Text-to-SQL sobre DuckDB corporativo.

Python 3.13+ FastAPI ASGI DuckDB 1.5+ Groq LPU 70B SHA-256 Audit Chain

1. Visão Geral

O Milia AI é uma plataforma analítica corporativa e agente conversacional Text-to-SQL com governança rigorosa em profundidade. O sistema converte perguntas de negócio expressas em português livre em consultas SQL determinísticas, otimizadas e seguras, executadas sobre o motor colunar DuckDB.

Regra Fundamental de Negócio

No ecossistema corporativo da Milia, a métrica oficial de faturamento, receita ou vendas é sempre mapeada compulsoriamente para a coluna "Valor Contábil" (ex: SUM("Valor Contábil")). Colunas como Fat. Bruto não existem na base e são estritamente rejeitadas.

Perfis de Acesso e Matriz de Permissões

Perfil / Tag Unidade de Negócio (BU) Escopo de Visualização Capacidades
Colaborador Padrão Varejo Exclusivo da própria BU Consultas analíticas restritas aos dados de sua unidade. Tentativas de acessar outras BUs são interceptadas no RLS.
Especialista Serviços ou Corporativo Exclusivo da respectiva BU Análise detalhada de clientes, produtos e margens da sua divisão.
Acesso Global Todas as BUs Irrestrito Corporativo Exige as 3 tags simultâneas: fiscal, contabil e adm. Permite consolidado de todas as unidades.
Administrador Qualquer BU Painel de Gestão & Auditoria Aprovação de usuários pendentes, verificação de integridade SHA-256 e visualização de incidentes.

2. Arquitetura do Sistema

O sistema foi projetado sob o princípio de desacoplamento estrito e defesa em profundidade. A camada de apresentação (SPA moderna acelerada com GSAP 3) comunica-se exclusivamente com a API RESTful em FastAPI, que atua como barreira perimetral antes de qualquer contato com o modelo de inteligência artificial ou motor analítico.

flowchart TD Client["Client Web (SPA / GSAP 3)"] -->|POST /api/chat/query| FastAPI["Gateway FastAPI (app.py)"] FastAPI --> RL["RateLimiter (Sliding Window 60s)"] RL --> CB["SecurityCircuitBreaker (3 Strikes / 15m)"] CB --> Scope["ScopeGuardrail (Intenção & Anti-Injection)"] Scope --> Agent["AnalyticalAgent (Prompt Engine)"] Agent --> Schema["DuckDB Schema Introspection"] Agent --> Groq["GroqCloud (Llama 3.3 70B LPU)"] Groq -.->|Fallback 429| GHModels["GitHub Models (gpt-4o-mini Azure AI)"] Groq --> RLS["RLSEnforcer (Isolamento por BU)"] GHModels --> RLS RLS --> SQLG["SQLGuardrail (Auto LIMIT 100 & AST Check)"] SQLG --> DBM["DatabaseManager (DuckDB Read-Only)"] DBM --> DuckDB[("banco.duckdb")] DBM --> Render["_render_template (Renderização Local em Python)"] Render --> Client Render -.-> Audit["ImmutableAuditService (Hash SHA-256)"] Audit --> SQLite[("users.db (SQLite)")]

3. Fluxo de uma Requisição: As 7 Esteiras Sequenciais

Toda mensagem enviada pelo usuário percorre obrigatoriamente 7 esteiras de controle contínuo implementadas no método execute_chat_query em src/sql_agent/chat/router.py. Nenhuma etapa pode ser pulada.

0
Perímetro de Segurança & Proteção de DoS

O SecurityCircuitBreaker verifica se o usuário está suspenso por infrações repetidas de segurança. Em seguida, o RateLimiter garante que a quota máxima de 30 requisições/minuto em janela deslizante de 60s não seja excedida.

1
Input Guardrail (Escopo, Ambiguidades e Prompt Injection)

O ScopeGuardrail avalia o texto do usuário:
• Saudações / Descoberta de Schema: Responde imediatamente sem acionar a LLM, economizando tokens e latência.
• Perguntas Ambíguas: Solicita esclarecimento antes de gerar consultas desnecessárias.
• Prompt Injection / Fuga de Escopo: Bloqueia tentativas adversariais e grava incidente com severidade CRITICAL.

2
Text-to-SQL Agent (Compilação Semântica)

O AnalyticalAgent introspecta o schema oficial do DuckDB em tempo de execução e submete ao modelo (Groq ou GitHub Models com temperature=0.0). O modelo compila a intenção em um JSON com SQL sugerido e um row_template de exibição.

3
Row-Level Security Enforcement (RLS)

O RLSEnforcer valida se o usuário possui acesso global. Caso contrário, qualquer menção a outra Unidade de Negócio é interceptada com risk_type="Violação de BU" e a cláusula da BU do usuário logado é aplicada.

4
Auto LIMIT 100 & SQL Guardrail (Blindagem AST)

O SQLGuardrail injeta compulsoriamente LIMIT 100 no SQL, verifica se a query começa estritamente com SELECT ou WITH, rejeita múltiplos statements (;) e bloqueia comandos DDL/DML.

5
DuckDB Execution Sandbox (Modo Read-Only)

O DatabaseManager submete a query ao comando EXPLAIN. Se o custo computacional for $\ge 5000$, a query é cancelada preventivamente. A execução ocorre com timeout de 30s e teto de 5 MB de resultado em memória. Em caso de erro sintático, o mecanismo de Self-Healing tenta corrigir o SQL em até 2 rodadas.

6
Renderização Local Zero-Trust & Trilha de Auditoria

Os dados do banco NUNCA são reenviados para a LLM. O método _render_template em Python preenche as variáveis no template localmente com formatação monetária (R$). A transação é registrada na trilha com hash encadeado SHA-256 e redação PII (LGPD).

4. Integração e Ciclo de Vida da LLM

Para assegurar resiliência contínua, o sistema implementa alta disponibilidade através do método .with_fallbacks() do LangChain:

src/sql_agent/config/settings.py 
# Fábrica de LLM com Failover Transparente
if primary_llm and fallback_llm:
    # Se a Groq atingir HTTP 429 ou indisponibilidade, GitHub Models assume instantaneamente
    return primary_llm.with_fallbacks([fallback_llm])
elif primary_llm:
    return primary_llm
elif fallback_llm:
    return fallback_llm
Conhecimento da LLM vs. Contexto da Aplicação

A LLM não possui memória prévia sobre as tabelas da Milia. O conhecimento vem 100% da introspecção em tempo real via fetch_database_schema() injetada dinamicamente no system prompt. Se uma coluna não estiver no schema, a IA é orientada a retornar SCHEMA_INSUFICIENTE.

5. Isolamento da LLM & Filosofia Zero-Trust

No Milia AI, a LLM é tratada estritamente como um compilador linguístico sem privilégios de acesso. Ela não faz parte do perímetro seguro interno.

Recurso do Sistema Acesso Direto pela LLM? Mecanismo que Garante o Bloqueio
Conexão DuckDB NÃO O objeto DuckDBPyConnection é exclusivo do processo Python local. A LLM só troca strings via HTTP.
Linhas / Dados Retornados NÃO A função _render_template formata os dados localmente no backend. Nenhum dado de faturamento é reenviado à IA.
Banco de Usuários (SQLite) NÃO A tabela users.db sequer é informada no prompt do sistema.
Sistema Operacional / Disco NÃO Nenhum interpretador de código, subagente ou tool de shell está habilitado para o modelo.
Isolamento de Outras BUs NÃO O RLSEnforcer intercepta o SQL após a geração e aplica o filtro obrigatório da BU.

6. Segurança em Profundidade

Trilha de Auditoria Imutável com Hash Encadeado (SHA-256)

Cada registro gravado na tabela immutable_audit_log é criptograficamente encadeado ao hash do registro anterior, formando uma estrutura Merkle sequencial. Triggers nativos no SQLite proíbem comandos UPDATE e DELETE:

Triggers de Proteção no SQLite (src/sql_agent/security/immutable_audit.py) 
CREATE TRIGGER IF NOT EXISTS trg_immutable_audit_no_update
BEFORE UPDATE ON immutable_audit_log
BEGIN
    SELECT RAISE(FAIL, 'VIOLAÇÃO DE AUDITORIA: Registros imutáveis não podem ser modificados.');
END;

CREATE TRIGGER IF NOT EXISTS trg_immutable_audit_no_delete
BEFORE DELETE ON immutable_audit_log
BEGIN
    SELECT RAISE(FAIL, 'VIOLAÇÃO DE AUDITORIA: Registros imutáveis não podem ser removidos.');
END;

Redação de PII e Proteção LGPD

O componente PIIRedactor mascara automaticamente CPFs, cartões de crédito, telefones e e-mails antes de qualquer persistência em logs de telemetria ou auditoria.

7. Modelo de Ameaças (Threat Model)

Ameaça Possibilidade Mitigação Existente no Código Limitação / Risco Residual
Prompt Injection Média Regex pré-compiladas no ScopeGuardrail bloqueando jailbreaks antes de chamar a IA. Injeções inéditas ou com ofuscação não prevista no dicionário podem alcançar o modelo.
SQL Injection DDL/DML Muito Baixa Conexão estrita read_only=True; proibição de múltiplos statements (;); bloqueio de comandos DDL. Injeção de filtros analíticos (OR 1=1) pode alterar o recorte de visualização.
Vazamento entre BUs Baixa RLSEnforcer valida e injeta o filtro da BU do usuário logado na query compilada. Usuários com Acesso Global legítimo podem visualizar todas as BUs corporativas.
Negação de Serviço (DoS) Baixa Injeção compulsória de LIMIT 100; barreira de custo computacional EXPLAIN (< 5000); teto de 5MB. Consultas pesadas em bases gigabyte podem consumir picos temporários de CPU até o timeout de 30s.
Abuso de API por Força Bruta Muito Baixa RateLimiter (30 req/min) e SecurityCircuitBreaker (suspensão de 15 min). Os contadores residem na memória do processo; reiniciar o servidor reseta a janela.
Adulteração de Auditoria Baixa Triggers SQLite proibindo UPDATE/DELETE; encadeamento SHA-256 verificado matematicamente. Acesso de escrita root direto ao arquivo users.db no SO poderia recalcular a cadeia.

8. Decisão Arquitetural: Text-to-SQL vs. RAG Vetorial

Por que o projeto NÃO utiliza RAG (Embeddings / Vector DB)?

RAG vetorial fatiaria relatórios e realizaria busca por similaridade de cosseno. Para perguntas numéricas como "Qual o faturamento total da BU Varejo em 2026?", o RAG forçaria a LLM a calcular somas mentais sobre milhares de pedaços de texto, gerando alucinações e erros contábeis inaceitáveis. O Text-to-SQL sobre DuckDB executa somas analíticas determinísticas em milissegundos com precisão decimal exata.

11. Guia de Execução e Testes

1. Instalação do Ambiente

Terminal (Bash / PowerShell) 
# Criar ambiente virtual
python -m venv .venv
source .venv/bin/activate  # No Windows: .venv\Scripts\Activate.ps1

# Instalar dependências
pip install -r requirements.txt

# Configurar variáveis de ambiente
cp .env.example .env

2. Inicialização do Servidor Web

Terminal 
uvicorn app:app --host 127.0.0.1 --port 8000 --reload

Acessos disponíveis:

  • Chat Analítico / Login: http://127.0.0.1:8000
  • Documentação Técnica Interativa: http://127.0.0.1:8000/documentation
  • Swagger OpenAPI: http://127.0.0.1:8000/docs
  • Endpoint Prometheus: http://127.0.0.1:8000/metrics

3. Execução dos Testes Automatizados

Terminal 
# Executar todos os 32 testes automatizados
python -m pytest tests/ -v

12. Guia de Extensão do Sistema

1
Adicionar Nova Coluna ou Métrica de Negócio

1. Adicione a coluna em minúsculas na DEFAULT_ALLOWLIST["faturamento"] em src/sql_agent/guardrails/sql_guardrail.py.
2. Documente o campo no _SYSTEM_PROMPT em src/sql_agent/v2/agent.py incluindo pelo menos um exemplo *few-shot*.
3. Se a métrica tiver apelidos informais, mapeie a regex no _sanitize_generated_sql.

2
Adicionar Nova Unidade de Negócio (BU)

Adicione a nova BU no conjunto KNOWN_BUS em src/sql_agent/guardrails/rls_enforcer.py e atualize o catálogo de usuários no SQLite se necessário.
